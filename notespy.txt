# КОМАНДЫ ДЛЯ ПРОВЕРКИ MicroPKI В CMD ЧЕРЕЗ py

Эта версия предназначена для Windows CMD, то есть для обычной командной строки cmd.exe.

Важно:

* В CMD перенос строки делается символом ^
* Символ ^ должен стоять в самом конце строки.
* После ^ не должно быть пробелов.
* В PowerShell эти команды с ^ работать нормально не будут.
* В Linux вместо py используется python3, а перенос строки делается через \

1. ПЕРЕЙТИ В КОРЕНЬ ПРОЕКТА

---

cd C:\Users\User\Documents\GitHub\MicroPKI

Нужно перейти в папку проекта, где лежат папки micropki, tests, demo и файл README.md.

11. СОЗДАТЬ ПАПКУ ДЛЯ СЕКРЕТОВ

---

mkdir pki\secrets

Пояснение:
Создаётся папка для passphrase-файлов.

12. СОЗДАТЬ PASSPHRASE ДЛЯ ROOT CA

---

echo RootPass123!> pki\secrets\root.pass

Пояснение:
Создаётся файл с паролем для шифрования закрытого ключа Root CA.

Важно:
В команде специально нет пробела перед >, чтобы лишний пробел не попал в пароль.

13. СОЗДАТЬ ROOT CA

---

py -m micropki ca init ^
--subject "CN=Demo Root CA,O=MicroPKI,C=RU" ^
--key-type rsa ^
--key-size 4096 ^
--passphrase-file pki\secrets\root.pass ^
--out-dir pki ^
--validity-days 3650 ^
--force

Пояснение:
Создаётся самоподписанный Root CA.

После выполнения должны появиться:

pki\private\ca.key.pem
pki\certs\ca.cert.pem
pki\policy.txt

14. ПРОВЕРИТЬ ROOT CA ЧЕРЕЗ OPENSSL

---

openssl x509 -in pki\certs\ca.cert.pem -text -noout

openssl verify -CAfile pki\certs\ca.cert.pem pki\certs\ca.cert.pem

Ожидаемый результат:

pki\certs\ca.cert.pem: OK

Пояснение:
Проверяется, что Root CA корректно создан.

15. ИНИЦИАЛИЗИРОВАТЬ SQLITE-БАЗУ

---

py -m micropki db init --db-path pki\micropki.db

Пояснение:
Создаётся база данных для сертификатов.

16. СОЗДАТЬ PASSPHRASE ДЛЯ INTERMEDIATE CA

---

echo InterPass456!> pki\secrets\intermediate.pass

Пояснение:
Создаётся файл с паролем для закрытого ключа Intermediate CA.

17. СОЗДАТЬ INTERMEDIATE CA

---

py -m micropki ca issue-intermediate ^
--root-cert pki\certs\ca.cert.pem ^
--root-key pki\private\ca.key.pem ^
--root-pass-file pki\secrets\root.pass ^
--subject "CN=Demo Intermediate CA,O=MicroPKI" ^
--key-type rsa ^
--key-size 4096 ^
--passphrase-file pki\secrets\intermediate.pass ^
--out-dir pki ^
--validity-days 1825 ^
--pathlen 0

Пояснение:
Создаётся Intermediate CA, подписанный Root CA.

После выполнения должны появиться:

pki\private\intermediate.key.pem
pki\certs\intermediate.cert.pem
pki\csrs\intermediate.csr.pem

18. ПРОВЕРИТЬ INTERMEDIATE CA ЧЕРЕЗ OPENSSL

---

openssl verify -CAfile pki\certs\ca.cert.pem pki\certs\intermediate.cert.pem

Ожидаемый результат:

pki\certs\intermediate.cert.pem: OK

Пояснение:
Проверяется, что Intermediate CA подписан Root CA.

19. ВЫПУСТИТЬ SERVER-СЕРТИФИКАТ

---

py -m micropki ca issue-cert ^
--ca-cert pki\certs\intermediate.cert.pem ^
--ca-key pki\private\intermediate.key.pem ^
--ca-pass-file pki\secrets\intermediate.pass ^
--template server ^
--subject "CN=localhost,O=MicroPKI" ^
--san "dns:localhost" ^
--out-dir pki\certs ^
--validity-days 365

Пояснение:
Создаётся серверный сертификат для localhost.

Для server-сертификата SAN обязателен.

20. ВЫПУСТИТЬ CLIENT-СЕРТИФИКАТ

--ca-cert pki\certs\intermediate.cert.pem ^
--ca-key pki\private\intermediate.key.pem ^
--ca-pass-file pki\secrets\intermediate.pass ^
--template client ^
--subject "CN=Demo Client,O=MicroPKI" ^
--san "email:client@example.com" ^
--out-dir pki\certs ^
--validity-days 365

Пояснение:
Создаётся клиентский сертификат с назначением clientAuth.

21. ВЫПУСТИТЬ CODE SIGNING-СЕРТИФИКАТ

25. ПРОВЕРИТЬ ЦЕПОЧКУ СЕРТИФИКАТОВ

---

--cert pki\certs\localhost.cert.pem ^
--intermediate pki\certs\intermediate.cert.pem ^
--root pki\certs\ca.cert.pem

Ожидаемый результат:

Chain validation PASSED: leaf → intermediate → root

Пояснение:
Проверяется цепочка:

localhost certificate -> Intermediate CA -> Root CA

53. ЧАСТЫЕ ОШИБКИ В CMD

---

Ошибка:
the following arguments are required: --subject, --passphrase-file

Причина:
Команда была оборвана. Скорее всего, перенос строки написан неправильно.

Решение:
В CMD использовать ^ в конце каждой строки.
После ^ не должно быть пробела.

Ошибка:
Отсутствует выражение после унарного оператора "--"

Причина:
Команда с ^ была запущена в PowerShell, а не в CMD.

Решение:
Открыть cmd.exe или терминал PyCharm в режиме Command Prompt.

Ошибка:
intermediate.cert.pem not found

Причина:
Команда issue-intermediate раньше упала.

Решение:
Проверить вывод выше и убедиться, что Root CA успешно создан.

Ошибка:
Certificate object has no attribute not_valid_before_utc

Решение:
Обновить cryptography:

py -m pip install --upgrade cryptography

или применить compatibility patch.

Ошибка:
unsupported operand type(s) for |: 'type' and 'NoneType'

Причина:
Проект запускается на Python 3.8, а в коде есть аннотации Python 3.10 вида str | None.

Решение:
Добавить в начало соответствующего .py файла:

from **future** import annotations

или заменить str | None на Optional[str].
